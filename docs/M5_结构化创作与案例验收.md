# M5 结构化创作与案例库分项验收

日期：2026-10-01。实现八个新增创作Stage、结构化剧本与台词数据、跨稿型候选、案例库本地持久化及公开资料读取。真实模型生成和完整交接验收仍未完成。

## 创作合同与本地流程

新增构思、大纲、小说正文、场次剧本、文案、文字来源拆解、仿写新方案、改编映射的共同输出合同。HTTP/CLI使用相同语义schema，程序检查字段类型、未知字段、枚举、ID、依赖成环、人物引用、对白顺序及保留事件去向。不把JSON语法合法等同于完整作品。

候选先显示再审核，作品可以作为同项目的新文档采用，来源稿和版本保留。小说与文案不被强加剧本字段；切换入口不自动转换旧稿型。已确认大纲可落实到稳定目录ID，重复操作不重复建节点，已有正文保留，锁定节点会阻止AI修改。

剧本保存场次、动作/对白块及speaker_id。逐句对白锁保留原文、人物绑定与顺序；手工改动作仍可保存。锁定在生成后新增也会阻止采纳冲突候选。结构化文稿手改时保持语义数据一致；未识别格式保留内存稿并拒绝静默丢内容。

已确认剧本可导出“大纲与建议时长 / 完整剧本 / 完整人物台词”三部分。台词本从确认数据顺序提取，没有再次模型抄写。时长均标预计；对白语速、停顿、动作和转场初值可调，手改后重估，不宣称音频实测。

来源拆解只根据实际文字/字幕/分镜，证据须定位段落ID，未知项单独保存；没有视频画面时固定为text_only。仿写/改编先保存确认方案，保留事件要有目标节点映射，不覆盖来源。相似表达只列重复片段，不出相似度百分比或侵权保证。来源变更使旧映射过期，对照使用最初关联的来源版本。

## 案例库

本地独立库导入原附件六部作品和七条改编关系，原字段与未知指标保留。支持身份编辑、JSON/CSV映射预览导入、筛选、收藏、回收恢复、导出与历史版本；同名不同年不自动合并。

详情五页签分概况、成绩来源、改编关系、结构研究与方法。散文集不变成小说，多原作关系不互相覆盖。评分保留平台、满分、人数和采集日期；票房保留币种、地区、期间及截止日期；奖项区分获奖/提名/入围/推荐并绑定实际影视或原著对象。微短剧指标不能混用播放、流水、消耗、分账。

方法为用户撰写的待审候选，审核后才加入当前项目规则；项目冻结方法及必要案例版本，不发送整库。当前尚未实现自动从完整剧作提炼方法，不能把元数据候选当成已证明规律。

公开资料工具只读取用户本次明确选择的公开HTTPS地址，不传KEY/作品，不执行网页指令；受限或无法解析时明确失败，不绕过登录付费限制。没有在本轮做全量年份采集；覆盖页面明确未检索年份，不将未知记零。

## 验证

累计124项unittest通过，M5新增25项（14项结构化写作、9项案例、2项公开资料边界）。证据涵盖人物绑定/顺序错误拒绝、新稿来源保留、确认对白确定性导出、动作改写不改锁定对白、未识别文本不丢、大纲ID/依赖/节点锁、改编保留项去向、来源过期拒绝、种子关系/未知值、同名版本、评分历史与筛选、票房口径、奖项对象、方法候选审核及回收导出。

`tools/writing_ui_acceptance.py`六项实际Qt检查通过：候选不改原稿、采用同项目新文档、确认后导出台词、片名筛选/散文类型、多原作保留、五页签与未知评分。模型响应固定并隔离，界面明确标记，不是实际服务商生成。截图 `docs/evidence/ui_结构化剧本与人物绑定.png`、`ui_案例库五页签与来源关系.png`；结果 `writing_ui_results.json`。

源码入口实际启动成功。开发中发现附件电视作品形式为`television_series`，已保留实际值并修正校验，未以简写误覆盖种子。
