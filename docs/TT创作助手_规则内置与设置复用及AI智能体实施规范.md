## 1 本次确定的产品方向

软件继续保留五个一级页面：**首页、创建剧本、创建小说、仿写内容、设置**。核心是用户选好方向，输入简单想法或留空，由 AI 创作；已有作品也能在右侧 AI 助手中直接讨论、检查和提出修改。不得把软件做成人工写完以后才让 AI 复核的工具。

本次方案收敛为三件事：

1. 收起独立的“资料与规则”管理入口，规则在内部运行；创作页的赛道、细分、风格、时长等选择继续保留，仿写参考输入继续保留。
2. 设置页复用 TT影序已核实的三套界面及连接逻辑，保持原布局、控件层级和主要文案，不再另造一套设置交互。
3. 做一个真正连接当前作品的 AI 助手：能找到相关内容、理解范围、调用受限工具、形成可检查的修改，并保护原稿和历史版本。

成功标准是实际任务完成质量、正确修改范围、稳定性和用户操作成本。“千万级”不作为可验证的技术等级，也不以接入某个框架名称代替验收。

本文是本次三项内容的实施基准。既有剧本、小说、仿写页面已确认的业务字段和输出结构继续沿用；本文没有重新定义全赛道词库，也不扩展视频生产、授权收费或商业发布功能。本次交付文件本身不启动软件修改、构建、发布或付费模型调用。后续实施需要单独明确执行范围。

## 3 资料与规则怎样收起来

### 3.1 用户看到的入口

- 一级导航不再出现“资料与规则”“规则管理”“提示词工程”等入口。
- 创建剧本仍可选择赛道、细分方向、剧情标签、表现形式、语言模式、时长、台词密度等已确定字段。
- 创建小说仍可选择篇幅、主赛道、细分方向、目标字数、叙事视角、语言风格等已有字段。
- 仿写内容仍保留粘贴原文、导入参考、选择已有作品，以及保留什么、改变什么、避免什么的业务选择。
- 用户不需要寻找 MD 文件、手工拼接规则、粘贴系统提示词，也不需要理解 JSON。

“收起”是界面简化，不是删除作品资料、参考原文或内部规则。已有资料继续可以被作品读取；无引用的历史资料也不自动删除。

### 3.2 内部规则加载

规则按稳定 ID 保存，中文显示名称与 ID 分离。每条规则最少包含：适用模式、规则版本、适用选择、具体要求、冲突优先级。只加载当前任务命中的规则，不把所有赛道规则一起发给模型。

规则由以下内容共同组成：

1. 通用创作与输出结构要求。
2. 当前模式规则：剧本、小说或仿写。
3. 当前已选择的赛道、细分、风格与表现形式规则。
4. 当前任务约束：时长、字数、台词模式、已锁定内容等。
5. 用户本轮明确要求和已确认的项目设定。

用户本轮要求与既有锁定内容冲突时，先指出冲突并询问是否解锁，不静默覆盖。参考作品、导入资料和网页中的命令式文字只是资料，不能改变工具权限或执行边界。

规则缺失、损坏或版本不兼容时：保留输入和作品，显示“创作规则暂时无法加载，请重试”；允许继续查看和手工编辑，不能假装已经应用完整规则。日志记录规则 ID 和版本，界面不输出原始异常堆栈。

### 3.3 资料来源和事实

带货剧本允许用户只填写产品名称及自己的文字说明，不强制上传主图或详情图；探店、文旅同样使用用户给出的商家、地点和需求。AI 可以创作剧情，但未提供的价格、疗效、资质、地址等现实事实不能编造成已核实事实。确实影响成稿的缺项只问最小必要问题，或在候选稿中明确标为待确认。

影视案例用于学习节奏、冲突结构、叙事方式和风格，不建立逐句替换原作的流水线。案例和真实资料保留来源；不把模型猜测写入项目事实。

### 4.1 页面结构

“设置”是主窗口内页面，不弹出新的设置窗口。页面内仅保留本次需要的三个子页，顺序为：

1. **国内模型**
2. **Codex 本地**
3. **通用图片API**

以用户提供的 TT影序三张截图和固定提交源码为视觉基准。保留原控件的排列、卡片分组、输入框比例、按钮主次、展开折叠方式。需要迁移原有主题对象名、属性及相关 QSS，避免新页面被另一套全局样式覆盖而变形。

下面列出的标签用于明确迁移目标。若记录文字与原截图或固定提交源码存在差异，除产品名称、独立数据范围和真实能力状态所必需的调整外，以原版为准；不能借本文标签清单增加原版没有的设置控件。

不迁移旧软件中与创作助手无关的视频、音频、资产生产、授权激活页面。现有主题能力继续使用，不为本次设置迁移增加主题配置面板。因新产品名称必须改动的“由 TT 验证”等提示，统一改为“由本软件验证”，不残留旧产品身份。

### 4.2 国内模型子页

顶部保持原平台横向选择，支持火山、DeepSeek、千问及第三方中转。正式平台名称以源程序显示词为基础，不为同一平台创建多个重复入口。

中部保留以下字段和按钮：

- “接口地址”
- “接口密钥”，密码显示；提示“留空则继续使用已安全保存的密钥”
- “模型（可搜索／可展开）”，允许搜索与手工填写模型 ID
- “刷新模型列表”
- “测试连接”
- “保存当前接口设置”
- “申请/管理官方 API Key”，只打开对应官方页面
- “删除已保存密钥”

底部保留“启用当前模型”和“清除本机保存的全部密钥”。后者仅影响 TT创作助手自己的密钥库，确认提示必须明确范围，不得清理 TT影序的数据。

行为约定：

- 保存某个平台，只保存该平台的配置；“保存”与“启用”分开。
- 表单未保存时点击启用，先提示保存，不悄悄使用半新半旧的配置。
- 刷新列表失败仍可手填模型 ID；不能将模型列表返回成功等同于文本生成成功。
- “测试连接”可使用表单中的临时配置，但不自动保存或切换默认模型。若测试会发起计费请求，界面先说明是小额文本测试；不得进入页面就后台生成。
- 密钥输入留空表示继续使用已保存值，不能被解释成删除。
- 已发出的任务固定使用发送时的渠道和模型快照；切换默认模型只影响后续请求。

### 4.3 Codex 本地子页

保持原版两行两列卡片：

| 位置 | 卡片标题 | 保留内容 |
|---|---|---|
| 左上 | Codex 状态 | 检测状态、登录状态、版本；“重新检测”“登录 / 重新登录” |
| 右上 | 图片生成渠道 | Codex Image 标识、当前图片渠道与能力状态；“设为当前图片生成渠道” |
| 左下 | 本地运行 | 已检测程序、模型来源、运行方式；“重新读取环境” |
| 右下 | 能力检测 | Codex Exec、登录授权、imagegen、实际生图四项分别显示 |

下方“高级设置 ▸”默认折叠。展开后保留程序路径、自动检测来源、可选语言模型覆盖，以及“选择程序”“保存路径”“恢复自动检测”“保存模型设置”。模型覆盖留空时跟随本机 Codex 配置，不虚构固定可用模型名。

四项能力状态必须分别成立：

1. 找到 CLI 程序不等于已登录。
2. 已登录不等于当前账号具备所需能力。
3. 找到 imagegen 不等于图片任务能成功。
4. 实际生图成功只能来自本软件经用户触发的真实任务，并记录渠道、版本、模型和时间。

TT影序历史成功记录不能直接迁移成新软件“已通过”。环境变化后历史成功可显示为历史记录，不能当作当前保证。未通过实际生图时显示“可尝试，尚未验证”，不要显示“全部正常”。

Codex 文本调用走独立适配器，优先使用只读、结构化输出的受限会话。不能为了让创作助手“更智能”，给其任意修改整个项目目录、执行任意命令或读取无关个人文件的权限。登录交互使用官方流程，软件不收集账号密码。

保持原版纵向结构：

1. 顶部“已保存网站”选择。
2. “服务连接与模型（国内／海外接口）”卡片。
3. “按平台文档填写画幅、尺寸与质量”卡片。
4. “费用读取与估算”卡片。
5. 底部操作行。

保留原字段：兼容模式、Base URL、API Key、Key状态、模型、尺寸策略、默认档位、手填size、质量、支持画幅及其他画幅。保留“读取模型列表”“保存模型”“启用费用估算”“读取费用”“确认并应用读取价格”。

底部按钮为“检查本地配置”“测试连接”“保存设置”“设为当前图片生成渠道”“删除已保存Key”。

重要边界：

- 站点配置以协议和规范化地址隔离；密钥、模型、各模型尺寸和价格不能串站。
- 选择已保存站点，按原交互恢复其配置；需要切换渠道时必须是用户主动选择事件，初始化加载不能误触发。
- 不支持的专用协议不显示为可用；新增协议必须有真实适配器和测试，不能把“自动兼容”解释成兼容所有网站。
- 手填尺寸和价格是用户配置，不代表平台保证支持。接口返回模型名不代表该模型能生图。
- 未知价格显示“暂无法估算”，不能显示成免费；不同币种不能直接当作人民币套入原价格栏。
- 查询既有图片任务使用创建时的站点和凭据引用，不因当前站点切换而查错任务。

## 6 模型与智能体框架的选型

### 6.1 模型设置结论

- DeepSeek：作为首选配置方向，承担生成、修改和复核；具体模型 ID 从服务商列表或用户手填获得。
- 火山、千问：同等接入统一文本服务，可作为用户主动选择的主模型。
- 第三方中转：单独的站点配置，显示真实站点和模型，不伪装成官方渠道。
- Codex CLI：独立本机调用适配器；文本与生图能力分别判断。
- 封面生图：使用独立的当前图片渠道，不将文本模型下拉框同时充当生图配置。

默认使用用户当前选择的模型，不偷偷切到其他收费渠道。只有用户已经配置并明确允许的备用路线才可以在约定错误下启用，并显示实际使用渠道。模型列表、额度、价格和能力会变化，不能写死“所有模型都支持工具调用、视觉、思考模式或 JSON”。

每个“渠道＋站点＋模型”维护能力记录：`supports_tools`、`structured_output`、`streaming`、`cancel`、`usage`、`cache`、`image`。记录来自文档、配置还是本次实测，并区分支持、不支持和未验证；未知不能按支持处理。`cancel` 还需区分停止本地等待与服务端真正取消。模型、站点或 CLI 版本变化时，使相关旧实测状态失效。

不支持原生工具调用时，可由程序预先提供必要上下文，让模型输出经过 Schema 和工具白名单校验的单步规划，再由程序决定是否执行受限只读步骤；也可降级为只生成候选内容。不能靠无限解析模型自然语言来执行工具或命令。结构化能力也不足时仅保留普通文本建议，明确显示“当前模型使用基础助手模式”，不得宣称完整智能体能力。

### 6.2 开源项目怎样使用

DeepSeek 的 `awesome-deepseek-integration` 是接入项目目录，包含应用和框架链接，不是安装以后就自动得到记忆、权限、工具或完整产品体验的单一智能体。[官方项目说明](https://github.com/deepseek-ai/awesome-deepseek-integration)

Qwen-Agent 是真实的智能体框架，提供模型与工具等组件及示例；可参考其工具调用、上下文和应用组织方式。它的示例代码执行器并不意味着适合直接放开到商业桌面软件中。[Qwen-Agent 官方仓库](https://github.com/QwenLM/Qwen-Agent)

本项目方案选用 **LangGraph 作为单一流程编排层**，用于管理请求状态、工具循环、人工确认点、流式结果和恢复检查点。它可以混合确定性步骤与模型决策，不要求同时接入完整 LangChain 产品栈。[LangGraph 官方说明](https://docs.langchain.com/oss/python/langgraph/overview)

不同时叠加三套智能体框架。DeepSeek、千问、火山是可替换的模型接入；Qwen-Agent 作为参考与候选专项适配来源，不再运行第二套独立任务循环。LangGraph 的引入也不能重建一份与软件作品库分离的“第二套真数据”。

框架选型不代表已安装。实际开发先验证 Python、PySide6、所选 LangGraph 版本和现有依赖兼容性，锁定版本并保留依赖许可证说明。若存在硬性不兼容，提交具体证据和替代方案，不能无声更换架构。

## 7 右侧 AI 助手的最终交互

### 7.1 位置与控件

剧本、小说、仿写三个编辑页面共用右侧助手组件。主编辑区右上固定显示文字按钮“AI 助手”，图标只能辅助，不能仅靠一条窄缝让用户猜。

展开时，按钮显示“收起 AI”；侧栏顶部标题“AI 助手”，右侧提供收起图标，悬停提示“收起 AI 助手”。收起后原位置仍保留“AI 助手”按钮。收起不取消正在生成的任务，切换页面也不把结果写入另一作品。

侧栏从上到下仅有：

1. 标题和当前作用范围简短提示。
2. 对话与修改结果。
3. 底部一个模型选择和一个输入框，输入框内或旁边有发送按钮；生成期间同一位置变成停止按钮。

输入框占位：“说说你想怎么写或修改，也可以让我检查当前内容”。不要常驻显示工具列表、执行图、提示词、Token 配额、多套模型参数和一排无效快捷按钮。

模型下拉显示“平台 · 模型”，只列已配置且可选择的文本渠道。未配置项可保留但禁用并说明“尚未配置”；底部单一提示“请先配置模型”，提供“前往设置”。不能点击发送后才静默失败。

### 7.2 作用范围

默认随当前页面和文档自动绑定：有选区时优先处理选中文字；否则处理当前场景或当前章节；全文分析任务才按需读取全文。

范围提示示例：“当前剧本”“第 3 章”“已选 126 字”“仿写结果”。提示不是新的复杂操作栏。选区变化不应在生成途中改变本次请求范围；发送时冻结快照。

用户明确说“检查整本人物关系”，即使光标在第三章，也应识别为跨章节任务；如果代词或对象存在多个可能，先问一句，不自行选错作品。

### 7.3 修改结果

检查、讨论、提问只在聊天区答复，不改正文。明确要求修改时形成候选修改卡，卡片显示“修改了哪里”和简短原因，默认只保留主按钮“应用修改”；“查看对比”可展开，放弃操作在次级位置。

点击“应用修改”后原子写入一个新版本，显示“已应用，可撤销”。不弹出连续确认窗口。需要解锁已锁定台词、改变仿写参考原文或扩大到别的作品时，先单独确认。

生成新作品由“开始创作”等明确创作动作触发，创建作品初始版本；右侧助手对已有正文的局部修改仍走候选机制。不要让模型的一句“已修改”替代真实的应用操作。

### 7.4 显示状态

请求过程只显示必要的业务状态：“正在读取相关内容”“正在生成”“正在检查修改”“等待应用”。流式文字可以逐步展示，但流式中间片段不能写入正式正文。

失败时显示可以理解的原因和下一步，如“模型暂时不可用，原稿未改变”。详细诊断放折叠详情或日志。没有通过验证的结果不得显示“完成”。

## 8 真正智能需要的工作闭环

统一流程为：确定任务和范围 → 读取必要内容 → 模型决定是否补充读取 → 生成结果或候选修改 → 程序校验 → 用户应用 → 保存版本并更新关联记忆。

### 8.1 典型任务

- “第三章男主再狠一点，结尾别改”：读取第三章、相关人物设定和必要前后文，修改相关动作与台词，保留结尾，输出局部对比。
- “这段冲突为什么弱”：解释原因，可给示例，不自动替换原稿。
- “只检查，别续写”：仅输出问题和定位，不生成续章，不触发写入工具。
- “按这些选择写一个三分钟剧本”：读取当前创建条件和命中规则，直接生成已约定的完整结构；想法留空时也能创作。
- “把这里改成旁白加台词”：区分旁白和角色发言，重算估计字数与时长，按规则标明估算，保持正文与台词清单同源。
- “仿这个节奏，换成我的人物和商品”：分析节奏、冲突与节点，写入新的仿写结果，不改参考原文，不杜撰商品事实。

这里的“智能”来自模型判断、正确上下文、明确工具和可验证结果共同作用。接口接通和聊天流畅都不能单独证明上述闭环可用。

### 8.2 最小工具集合

内部工具名称可按代码习惯调整，职责必须等价：

| 工具职责 | 可读取或产生的结果 | 边界 |
|---|---|---|
| 读取当前工作 | 当前模式、文档、选区、版本 | 只读发送时绑定的项目 |
| 读取章节或场景 | 指定内容与稳定 ID | 按需读取，不默认整本注入 |
| 搜索作品内容 | 相关原文片段与出处 | 返回定位，不只返回无来源摘要 |
| 读取人物与设定 | 已确认事实、关系、状态 | 标明来源和失效版本 |
| 读取适用规则 | 命中的规则正文和版本 | 不返回全部词库 |
| 提交候选修改 | 结构化补丁与变化摘要 | 无权直接覆盖正文 |
| 校验候选内容 | 锁定、结构、引用和范围问题 | 关键校验由程序执行 |
| 准备封面提示词 | 基于作品的可编辑图片提示词 | 不自动调用收费生图 |

首版不需要浏览器控制、任意 Shell、任意脚本执行或任意文件写入工具。工具入参做严格校验，未知工具名拒绝执行，调用结果携带来源 ID。模型不能自行创造“保存成功”或“已经联网验证”的工具结果。

## 9 上下文的组装与项目记忆

### 9.1 每次请求的上下文

按稳定顺序组装：通用职责和工具规则 → 当前模式规则 → 本次命中的选项规则 → 已确认项目设定 → 目标原文与必要相邻内容 → 最近相关对话 → 本轮要求。

当前文档的未保存编辑也必须可见：发送前读取编辑器内存快照并记录其版本，不只读取磁盘旧稿。正文很长时，先建立章节索引，取目标范围、前后摘要和命中的原文证据；全文任务采用分段读取后汇总，明确覆盖范围，不声称一眼看完未读取部分。

上下文上限根据实际模型能力计算，给输出和工具返回预留空间。先去重和裁剪不相关历史，再压缩摘要；锁定台词、当前目标原文、人物身份与本轮要求不能因预算不足被悄悄丢弃。无法保留关键内容时先缩小任务或说明限制。

### 9.2 记忆保存什么

项目记忆包含：已确认人物与关系、世界设定、已发生事件、章节摘要、未解决伏笔、用户明确的项目约束。每条至少记录项目 ID、来源文档与版本、相关片段、确认状态和更新时间。

模型猜测、未采纳候选稿、聊天中的假设不进入已确认事实。修改或删除原文后，将受影响记忆标为失效并增量重建；存在冲突时以用户已确认事实和最新正文为依据，不能让旧摘要压过新稿。

剧本、小说和仿写可共用记忆存储机制，但不同项目隔离。仿写参考原文与创作结果分别标识，避免把原作人物设定混成当前作品设定。用户应能通过项目内的普通设定入口查看和修正事实，不必打开数据库或系统提示词。

### 9.3 缓存和记忆不是一回事

本地项目记忆保存作品事实；服务商上下文缓存用于复用重复请求前缀。DeepSeek 官方缓存按匹配情况生效，可从返回用量中识别命中，不能保证每次命中。[DeepSeek 缓存说明](https://api-docs.deepseek.com/guides/kv_cache/)

应用保持稳定规则前缀、按需检索正文、避免重复发送整本书。更新时间等每次变化的字段放到必要的动态区域，不插入稳定前缀破坏复用。不能为提高缓存命中而保留已经失效的事实。

不承诺“最低消耗”或“接 API 必然比网页强”。记录实测输入、输出、缓存用量及任务质量后，再比较同一任务的成本和效果。

## 10 补丁和数据安全

候选修改至少包含：`request_id`、`project_id`、`document_id`、`base_revision`、目标节点或范围、原文摘要哈希、修改类型、新内容及简短变化说明。

应用时同时检查项目、文档、版本、目标范围与原文哈希。只凭文本相似度全局替换不合格；重复台词、同名章节也必须准确定位。用户在等待期间改了正文，旧候选显示“原文已变化，请重新生成或重新对比”，不能强行覆盖。

每次应用是一次事务：先验证，再写正文、新版本及必要索引；任一步失败则全部回滚。连续点击“应用修改”只产生一次版本。撤销恢复对应版本，不删除较新的其他文档改动。

剧本正文和完整人物台词使用同一份有稳定 ID 的发言记录生成。改了台词需同步派生输出；两边都被人工修改时必须标出不同步并由用户选择处理，不直接丢掉任一边。

仿写参考保存不可变的本次源快照，后续替换参考属于新的输入版本。候选修改默认只作用于仿写结果。

## 11 费用 取消和恢复

默认单个请求使用一个主模型，不常态启动多个角色互相讨论。格式、锁定内容、字段引用、空结果、写入范围等能由本地代码判断的项目不再调用模型复核；语义难题才追加模型检查。

首版建议后台安全上限：普通助手请求最多 3 次模型往返、8 次只读工具调用；长篇创作和整本检查使用独立分段任务预算，不能偷偷突破普通预算。上限是可调整的产品默认值，不是模型能力结论；达到上限保留已完成结果并询问是否继续。

停止按钮立即阻止新的模型和工具步骤，并尽可能终止在途请求。若供应商已受理，界面说明“已停止后续步骤，本次请求可能仍计费”，不承诺撤回费用。

网络重试按错误分类：明确未发出、限流或可安全重试的读取可有限退避；已经获得任务 ID 的图片请求只查询原任务；请求是否已受理不明时标记“结果待确认”，不能盲目重新生成。用户连点发送、窗口重开和恢复检查点均不得产生重复任务。

检查点保存已完成步骤与外部任务 ID。进程重启后先对账再恢复，写入节点具有幂等键，不能因图恢复而重复应用补丁或重复生图。

## 12 封面生成的完整流程

封面入口仍属于作品，不新开复杂生产栏目。作品有正文时从大纲或摘要提取：题材、核心人物、关键场景、主要冲突、情绪、视觉风格、画幅和标题需求，自动填入可编辑提示词。

没有摘要时可先从当前正文生成短摘要；该过程使用当前文本模型，明确显示正在准备。没有正文时可使用已有创作条件，不能假装读取了不存在的作品。

提示词要求包含主体、构图、环境、光线与配色、风格、标题留位及必要限制。不要默认所有作品都黑暗电影风，也不要把内部分析和 JSON 控制字段混进生图提示词。标题是否直接由图片模型绘制，按用户选择和已知模型能力处理；不保证每个模型准确生成中文文字。

用户点击“生成封面”才向当前图片渠道发起任务。自动填提示词不自动付费生图。结果先预览，点击“设为封面”绑定到作品；重试生成新候选，不删除旧封面。记录提示词、渠道、模型、任务 ID、实际像素、文件哈希和生成时间。

TT影序原有图片结果归入资产库、镜像目录或视频项目的逻辑需替换为本软件封面资源归属，不带入旧工程的清理或复制流程。生成文件未落盘校验成功前不得显示“封面已保存”。

## 13 本地存储与迁移

沿用现有可靠的数据层，避免为了新框架重写整个项目存储。若当前已有 SQLite，可增加作品版本、任务检查点、项目记忆和模型使用记录表；若现有作品采用文件保存，保留其权威来源，SQLite 只做索引和事务记录，不同时维护两份独立正文。

推荐简单目录，具体位置遵循当前用户数据路径：

- `data/`：本软件数据库或现有项目数据、配置、密钥库与资源。
- `exports/`：用户导出的 Markdown、正文和封面。
- `logs/`：脱敏运行日志，设置轮换上限。
- `backups/`：升级前备份与必要恢复点，给出保留数量。

不按每次对话创建多层文件夹；检查点和消息优先作为数据库记录保存。导出文件名可读，内部资源用稳定 ID，避免作品改名导致资源丢失。可执行代码目录与用户作品数据分离。

迁移需要：版本号、迁移日志、完成标记、可恢复备份和幂等检查。迁移中断后再启动不重复导入；缺密钥不阻止打开作品。移除导航前验证历史资料、规则引用和作品都能继续读取。

密钥不进入明文项目文件、导出包、日志、聊天、提示词、测试截图或 Git。新软件使用独立密钥库和配置命名空间；旧软件加密文件不直接复制成新软件认证成功。Windows 密钥保护与系统用户关联，换电脑时应重新配置，不能假设搬文件即可解密。

模型调用只发送本次所需的作品内容；第三方中转应清楚标识接收方。默认关闭外部跟踪、分析上传和远程调试，框架不应自动向额外服务上传用户剧本。

## 14 界面与运行稳定性

复用原设置视觉基准，同时遵循现有已确认的 UI 交互规范。保留真实鼠标悬停、选中和键盘焦点的区别；下拉展开不推动整页跳动，不以反复重建控件实现联动。

网络、模型、文件索引和耗时迁移不阻塞 Qt 主线程。异步结果回到 UI 时核对目标和生命周期；页面关闭后不得回写已销毁控件，旧项目结果不得落到新项目。

多行输入、中文输入法、滚动位置与光标在状态刷新时保持稳定。隐藏卡片不留悬空占位；收起 AI 后编辑区合理扩展，重新展开恢复用户宽度，不把按钮挤出可视区域。

使用现有源码启动入口；子进程采用适合 Windows GUI 的启动方式，不不断弹 Python 小窗口。错误写入日志并给出用户可见提示，不靠闪退结束。

对 100%、125%、150%、200% 缩放及不同窗口宽度验证字体裁切、表单宽度、下拉边界和按钮可达性；软件缩放仿真不能替代所有真实高 DPI 测试，未测项必须标注。

## 16 后续实施顺序与完成定义

正式获得实施范围后，按以下顺序分阶段完成，每阶段保留可运行的源码版本：
