# TT创作助手：商业 UI 与交互静态审计及统一验收规范

日期：2026-10-03。状态：审计和设计建议，尚未执行新一轮 UI 升级。

## 结论与范围

主要问题是界面组件、信息角色和状态反馈尚未统一。继续按单张截图调整颜色、边框或字体，会使相同问题在剧本、小说和仿写中重复出现。应先固定共享组件及其全部状态，再统一接入三个栏目。

本轮依据用户明确提供的截图及直接相关 UI 源码做静态审计。没有打开实际软件操作流程，没有提交文本或图片生成，没有读取作品数据库、正文、历史响应或账号凭据；没有修改软件源码、安装依赖、构建或打包。只保存报告及六张原始截图证据。

截图可以证明可见布局和状态问题，源码可以证明当前入口及实现结构。按钮的运行结果、动效帧率、字体实际回退、屏幕缩放效果和滚动跳动根因仍需执行阶段定向验证。不能据此宣称完整流程已跑通或全面无障碍合规。

## 一、六个流程步骤的审计结果

| 步骤 | 用户任务 | 当前评价 | 证据与修订方向 |
|---|---|---|---|
| 1 | 首页进入剧本、小说或仿写 | 入口存在，实际行为有明确风险 | 截图出现 `False`；按钮回调未明确接收点击布尔参数。真实点击结果待复现。三个入口必须分别验收。 |
| 2 | 选择创作选项与展开细节 | 弹层外观有问题，位置稳定性待实测 | 下拉弹层粗黑边框、重阴影已由截图确认。展开涉及重排、焦点和滚动恢复，需要统一锚点规则。 |
| 3 | 生成作品并通过 AI 助手调整 | 状态可见，层级及操作反馈不足 | “正在构思”孤立、靠边；AI 对话、范围说明和项目元信息缺少明确组织。动态效果无法由静态截图判断。 |
| 4 | 编辑、撤销、查看版本及复制 | 常用功能隐藏，复制完整正文入口缺失 | 版本历史、撤销、重做、查找、阅读模式都应有稳定入口；需区分文本撤销与 AI 改稿撤销。 |
| 5 | 从首页生成封面 | 入口会跳转，比例和内容取材不符合最新要求 | 源码先打开项目；比例缺 9:16、4:3；提示词优先取正文前 1800 字。应改为原位弹窗、名称与大纲。 |
| 6 | 启用并识别当前使用模型 | 标签有标记，主操作反馈不完整 | 标签已有“当前启用”，底部按钮仍为“启用当前模型”；应同步变为“当前使用中”并处理未保存状态。 |

## 二、已经找到的源码依据

1. **首页三个按钮的参数风险。** [project_home.py](J:/精简版本/TTchuangzuo/app/ui/project_home.py:83) 使用 `lambda kind=kind` 绑定按钮回调。Qt 点击信号有布尔参数，该签名存在覆盖栏目参数的风险；与截图中 `False` 相吻合，但本轮没有执行点击复现。“新建项目”菜单的类似写法也应在同一项修复中检查。
2. **首页封面入口确实先跳转。** [v2_window.py](J:/精简版本/TTchuangzuo/app/ui/v2_window.py:707) 的 `open_home_cover` 先调用 `open_project`，再打开封面面板，最后设置返回位置。仅设置返回首页不足以做到原位弹窗。首页导出入口也调用打开项目，属于相同的上下文切换风险，应一起审计。
3. **封面取材确实优先读正文片段。** [cover_panel.py](J:/精简版本/TTchuangzuo/app/ui/cover_panel.py:78) 的 `auto_prompt` 优先取 `body[:1800]`，并附项目摘要；因此不是严格“只用名字与大纲”，也不能笼统说当前代码总是发送整篇完整剧本。
4. **封面比例列表确实不完整。** [cover_panel.py](J:/精简版本/TTchuangzuo/app/ui/cover_panel.py:37) 当前列表为 3:4、2:3、1:1、16:9，缺少用户指定的 9:16、4:3。
5. **常用工具仍藏在菜单。** [creation_page.py](J:/精简版本/TTchuangzuo/app/ui/creation_page.py:354) 与 [writing_page.py](J:/精简版本/TTchuangzuo/app/ui/writing_page.py:216) 分别组织作品菜单。编辑工具菜单包含查找、撤销、重做、阅读模式；这些功能存在，但可发现性不足。
6. **三个栏目仍分别拼装部分 UI。** 剧本页和小说／仿写页分别建立工具栏、底栏、作品菜单和视图恢复逻辑。共享颜色并不能保证入口、反馈和交互相同，应提升为真正的共享组件。
7. **焦点绘制存在叠加边框的设计风险。** [interaction.py](J:/精简版本/TTchuangzuo/app/ui/interaction.py) 同时有悬停边界和焦点覆盖层，样式还定义控件焦点边框。统一视觉出口，避免多层描边叠加；粗黑弹层的具体系统合成原因仍需实测。
8. **正文改字号会刷新整窗主题样式。** [v2_window.py](J:/精简版本/TTchuangzuo/app/ui/v2_window.py:137) 的 `set_font` 调用 `set_theme`。这种全窗刷新可能引起不必要的重绘或重排，应缩小到文字相关组件；本轮不声称已经测得卡顿。
9. **展开重排已有滚动恢复，但不能当成已解决。** [script_settings.py](J:/精简版本/TTchuangzuo/app/ui/script_settings.py:303) 的重排同时使用焦点锚点、卡片尺寸调整、延迟布局和滚动恢复。用户报告的跳动必须按真实点击顺序验证，不能在外层再叠加无依据的滚动补偿。
10. **模型启用反馈未覆盖主按钮。** 设置页已有当前启用标签，但主按钮主要调整可见性。需要把“浏览渠道”“已保存配置”“当前使用渠道”“存在未保存修改”统一映射到按钮文字及状态。

## 三、统一视觉基准：执行时先冻结这一套

以下是本产品的设计建议值，不是已经应用的效果，也不是外部标准要求的所有具体数值。尺寸按 Qt 逻辑像素设计，再在实际 DPI 下验收。

### 1. 文字层级

| 文字角色 | 建议默认字号 | 字重与用途 |
|---|---:|---|
| 页面标题 | 24 | 600；每页一个主要标题 |
| 分区标题／AI 助手标题 | 18 | 600；区分区域而不抢作品正文 |
| 导航与主要按钮 | 15–16 | 导航常规，主要动作 600 |
| 表单输入、菜单、对话正文 | 15–16 | 常规；不要所有内容统一加粗 |
| 字段标签 | 14 | 常规；使用次级文字色，仍需清楚可读 |
| 作品正文 | 18，可调 12–32 | 常规；保留用户已经确定的字号控制 |
| 项目元信息、快捷键、时间 | 13 | 辅助信息；不承担唯一的错误或状态说明 |

- 全界面使用一致的中文无衬线字体，验证实际中文和英文分别使用的字体，不只看配置名称。阅读字体可另设偏好，但不能让界面控件随正文切换字体。
- 中文字距保留自然排版，不通过手动插空格或夸大字间距制造“高级感”。
- 界面说明行高约 1.4–1.5 倍，长正文约 1.6–1.75 倍；段间距与空行分别处理，不篡改保存的正文文本。
- 作品名称、模型名称及菜单文本优先保证可读。空间不足时合理折行或省略并提供完整提示，不侵占复制、停止等常用按钮。
- AI 回复采用明确的标题、段落、列表和操作区层级；源文本、改稿结果、状态提示和操作链接要可区分。不能把原始 Markdown 标记直接当作排版层级。

### 2. 间距、尺寸与布局

- 统一间距档位：4、8、12、16、24、32；相同用途使用相同档位。
- 页面外边距约 24，卡片内边距 16–20，按钮间距 8，字段标签与输入框间距 6–8。
- 普通输入及主按钮高度 38–40，紧凑工具按钮约 32–36；图标小于点击区域，不把点击区域限制为图标本身。
- 顶部标题栏约 48，图标及软件名适度放大；若自定义标题栏，必须保留拖动、双击最大化、缩放窗口及 Windows 窗口操作。
- 左侧导航参考宽度约 160；正文文档选择框参考宽度 180–260，长章节名可以展开查看，不再无限占满工具栏。
- 圆角按角色分为控件 6–8、卡片 10–12；阴影集中在弹窗和浮层，普通表单依靠层次和细边框组织。
- 首页三个创建入口采用紧凑的图标、标题和一句说明，不保留三条占满整排的大色块作为唯一空态入口。已有作品时也应能清楚发现新建路径。
- 窄窗口优先折叠导航或将低频工具放入统一溢出菜单，保留复制全文、撤销、生成／停止等核心动作。不能只缩小字号。

微软 Windows 的内容布局指南将字号层级及稳定间距作为组织内容的基础，可作为一致性参考：[内容布局与间距](https://learn.microsoft.com/en-us/windows/apps/design/basics/content-basics)。上述具体尺寸是本产品建议。

### 3. 颜色语义

统一定义主文字、次级文字、占位文字、品牌色、选中背景、悬停背景、成功、警告、错误、边框、禁用等角色，三个主题只替换角色颜色。

- 主文字用中性色，品牌色用于主动作和明确选中入口，不把所有已填写字段都染成品牌色。
- “已填写”“当前焦点”“鼠标悬停”“已选中”“已启用”是不同状态，不能共用一圈粗深边框来表达。
- 错误使用图标、文字说明与适当颜色，成功和警告同样需要文字，不只依靠红绿区别。
- 普通文字以至少 4.5:1 的对比度作为设计验收基准；大文字的对应基准为 3:1。对比度需要按真实前景和背景计算，不能根据截图直接判定达标。该基准参考 [W3C 文字对比度说明](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)，本报告未宣称桌面软件全面通过 WCAG。
- 占位提示可以降低视觉权重，但不能淡到无法辨认；禁用控件应有可理解的不可用原因。

## 四、常用按钮与隐藏入口的完整分配

统一的正文上方工具栏：文档／章节、撤销、重做、查找、版本历史、字号、阅读模式、封面、导出。宽度不足时低频项进入分组溢出菜单，三个栏目使用相同规则。

统一的正文底栏：当前模型、保存状态、字数、复制完整正文、生成／停止生成。常用动作位置固定。

| 操作 | 常显或出现条件 | 交互要求 |
|---|---|---|
| 撤销／重做 | 正文工具栏常显 | 随编辑栈启用／禁用；对焦点所在编辑控件起作用，不误操作 AI 输入框或另一作品 |
| 版本历史 | 正文工具栏常显 | 列表显示时间与来源；预览、对比、恢复明确区分，不因浏览而恢复 |
| 查找 | 工具栏与快捷键 | 查找范围清楚；结果位置可辨认；关闭后恢复编辑焦点 |
| 替换 | 纳入编辑工具审计 | 先确认现有功能；若缺失，列入功能阶段。整篇替换要展示范围与结果，不能默默扩大作用范围 |
| 复制完整正文 | 底栏常显 | 复制当前文档全部正文，无内容时禁用，复制后显示“已复制”并回到常态 |
| 小说复制整本 | 多章节时提供明确入口 | 与复制本章区分；不附加 AI 对话、提示、元信息或未采用候选 |
| 封面／导出／导入 | 作品操作区 | 能够知道作用于哪部作品；首页操作保持当前首页上下文 |
| 生成／停止 | 底栏主操作 | 即时反馈、防重复点击；停止、等待结果、完成及失败分别显示 |
| AI 改稿对比／采用／放弃 | 候选存在时显著出现 | “编辑撤销”和“撤销本次 AI 改稿”分开表达，采用前不宣称正文已更新 |
| 处理正文与台词冲突 | 冲突发生时显示 | 提示位置固定，直接提供查看差异与处理入口；不靠贴边小字提示 |
| 锁定／解除锁定选区 | 选区操作区或右键菜单 | 展示当前选区及锁定状态，取消选区后不保留错误的操作范围 |
| 章节目录／新增章节／续写 | 小说对应状态 | 章节管理位置稳定，不让长篇能力因覆盖菜单而丢失 |
| 重命名／复制为新项目 | 作品操作菜单 | 用途清楚，不与“复制正文到剪贴板”混淆 |
| 删除／回收站／恢复 | 项目操作区 | 不与生成、复制紧挨混排；删除后有撤回或回收站路径 |
| 主题／动效强度／字体偏好 | 界面设置 | 五栏目同时应用；动效开关为全局能力，不只挂在剧本菜单 |
| 密钥清除等低频设置动作 | 对应设置区 | 与启用模型视觉分离，避免成为每次使用都面对的主要按钮 |

按钮统一覆盖默认、悬停、按压、键盘焦点、选中／启用、禁用、处理中、成功／失败反馈。没有必要的状态可以合并，但不能缺少“当前使用中”与“尚未启用”的区别。

快捷键先做清单与冲突审计，再统一实现。Ctrl+Z、重做、Ctrl+F、Ctrl+S 等动作应尊重焦点所在控件；复制全文提供独立入口，避免劫持普通 Ctrl+C。

## 五、动效规范

| 触发 | 建议效果 | 本产品建议时长 |
|---|---|---:|
| 按钮悬停／焦点变化 | 背景、颜色及单层细边框渐变，不改变布局尺寸 | 90–140 ms |
| 按下／释放 | 轻量颜色或深度反馈，立即执行动作 | 60–100 ms |
| 导航与标签选中 | 选中标识和背景平滑更新，正文不整页飞入 | 140–180 ms |
| 下拉菜单 | 柔和淡入、小幅位移，关闭更快；不出现黑色框底 | 120–180 ms |
| 局部展开／收起 | 对应区域高度平滑变化，稳定触发位置和滚动锚点 | 180–240 ms |
| 封面弹窗与 AI 面板 | 背景遮罩、内容进入协调，恢复时不改变原页面位置 | 180–240 ms |
| 复制／保存成功 | 图标或短状态切换，约 1–2 秒后恢复 | 非阻塞反馈 |
| 任务等待 | 小范围循环加载图标及真实状态文字 | 任务存在时运行 |

- 所有时长是统一的产品建议值，不宣称是官方强制值。动效应即时、用途明确、进入与退出方向一致；参考 [微软 Windows 动效指南](https://learn.microsoft.com/en-us/windows/apps/design/signature-experiences/motion)。
- 动画可中断，快速连续点击采用最后有效状态，不排队播放旧动画、不延迟停止请求。
- 悬停不重排页面；文字不反复缩放、不抖动，不用整页呼吸或持续彩色背景吸引注意。
- 字号调整尽量只更新相关文本组件；流式输出尽量局部更新，避免每个片段重建整个页面。
- 用户已在底部时可以跟随新内容；用户向上阅读后停止强制滚动，并提供“有新内容／回到底部”入口。
- 不知道进度时使用不确定进度提示，不虚构百分比或尚未发生的处理阶段。
- 提供“标准／减少动态”设置，并尊重系统减少动态偏好；减少动态模式仍保留文字和颜色反馈。
- 执行阶段记录短屏幕操作或逐状态截图，检查展开、下拉、缩放、发送／停止及关闭弹窗，而不是只验收静态首页。

## 六、SVG 与当前 Qt 技术路线

SVG 适合导航、编辑、复制、历史、封面和状态图标，保证缩放清晰及主题变色；部分加载图标也可以用可支持的 SVG 动画。它不能代替菜单行为、控件状态、布局、焦点和整个软件的动画系统。

建议优先沿用现有 PySide6 界面，把设计角色、共享控件和 Qt 动画统一起来。需要成熟 SVG 图标库时采用一致图标体系，不混用不同线宽的图标或文本符号。复杂效果若持续受限，再单独评估其他 Qt 界面技术，不能把“安装更多插件”当作解决交互一致性的方案。

Qt 官方将 SVG 渲染与界面动画作为不同能力提供：[SVG 渲染](https://doc.qt.io/qt-6/svgrendering.html)、[Qt 动画框架](https://doc.qt.io/qt-6/animation-overview.html)。网站示例里的 CSS／脚本 SVG 动画需要核验在当前桌面运行环境中的支持，不能直接假定可用。本报告不要求升级现有 Qt 版本。

## 七、封面交互与输入范围

- 首页点击生成封面，直接打开原位弹窗；不先进入项目编辑页，不更换当前编辑作品。
- 三个创作栏目复用同一封面弹窗；关闭时恢复原焦点、选中项目和滚动位置。
- 弹窗包含比例示意、风格、标题、文字方式、渠道、可编辑提示词、预览和采用。无图片时用清楚的预览空态，失败时保留用户已编辑提示词。
- 默认素材只有作品名称和故事大纲，结合用户选择的设计参数组织提示词。没有大纲时提示补充，不自动退回正文截取或项目记忆。
- 名称、概述及手工提示词可见可修改；“按当前作品重新填入”应防止无提示覆盖用户编辑内容。
- 常用比例为 3:4、16:9、9:16、4:3，保留 1:1、2:3；比例和实际像素尺寸分别显示，未支持的尺寸不冒充原生支持。
- 中文题材显示已解析的名称，不能把 G04 一类内部标识直接作为用户可读题材。
- 生成、查看候选、重新生成、采用分别是明确动作；关闭弹窗不应触发新的生成任务，未确认状态不能自动重发。
- 应核验“首页点击某项目封面，但此前打开的是另一个项目”这一场景，确保读写的是卡片对应项目。

## 八、减少返工的执行和验收顺序

1. **冻结规范与全页预览。** 固定字体、间距、颜色角色、按钮状态、弹层和动效；首页、三个创作页、设置、封面弹窗与 AI 面板一起展示，不能只看一页剧本。
2. **实现共享组件。** 统一标题栏、编辑工具栏、底栏、状态条、下拉弹层、提示／弹窗、AI 消息和模型使用状态。三个创作栏目通过内容与能力配置复用组件。
3. **先验证基础操作。** 首页三入口、选项选择、展开、撤销／重做、查找、复制、启用模型、封面原位打开及关闭恢复，全部用实际点击验证。
4. **再优化创作细节。** 在 UI 稳定后处理复杂版本对比、替换、长篇管理等缺项；既有数据真值与生成边界不得为视觉效果而改变。
5. **按矩阵定向验收。** 三个创作栏目均覆盖空正文、已有正文、生成中、已停止／失败、候选待采用、内容冲突这些状态。三主题至少验证共享组件，不把一个主题通过当作全部通过。
6. **覆盖真实显示条件。** 选择具有代表性的窗口大小及 Windows 100%、125%、150%、200% 缩放，检查文字裁切、弹层边框、鼠标命中、菜单越界和焦点；只有出现风险的组件补查，避免无意义重复。

验收清单必须记录：入口、前置状态、操作、应出现的反馈、应保持的上下文、通过证据。按钮存在、菜单出现或模拟回调成功都不足以代替真实点击结果。

### 必须通过的关键场景

- 首页三个按钮分别进入正确栏目，不显示 False 或内部参数。
- 剧本、小说、仿写的工具位置、复制、撤销、版本历史和生成／停止反馈一致。
- 没有正文时复制、导出、版本相关动作的状态与说明准确。
- 复制全文包含完整内容，用户选中片段不改变复制范围；复制整本不混入提示或未采用候选。
- 撤销普通编辑、撤销 AI 改稿、恢复历史版本各自作用范围清楚。
- 展开、关闭、快速重复点击不闪动，不自动跳到其他区域。
- 下拉菜单在三个主题与所选 DPI 下无粗黑边框，不越屏，选中项可见，Esc 能关闭并恢复焦点。
- 用户阅读上方内容时，新消息不抢走滚动位置。
- 配置正在查看的渠道、当前使用的渠道与未保存修改有区别；启用后主按钮显示当前使用中。
- 首页打开封面不跳栏目，关闭恢复首页；指定四种常用比例进入真实生成请求，默认提示词只用名字与大纲。
- 动效减少后界面依然可用，停止操作不等待动画结束。
- 键盘可访问常用操作，焦点有单层清晰标识；中文输入法不会被 Enter 提交逻辑误触发。
- 本轮 UI 升级仍不构建、不打包、不读取大量作品或原始响应；真实付费任务须遵守会话的生产确认边界。
